# RisuLua Modular Development Guide

This guide is for LLMs and developers working in a RisuLua workspace generated by scaffold or extract. Treat it as a source-ownership map: edit source modules, read generated sidecars for evidence, and avoid changing generated or audit outputs directly.

## Core rules

- Edit `lua/**/*.risulua` first; `lua/main.risulua` is the composition root and the other `lua/` folders are the editable module surface.
- Treat `dist/*.risulua` as generated package output and `legacy/original.risulua` as byte-for-byte audit/recovery input, not as primary development files.
- Read `docs/risulua-split-plan.json` and `docs/risulua-split-report.md` before moving code; optional sidecars explain domain grouping, host exports, duplicate globals, and button action usage.
- Starter modules may exist only to open an editing surface. They are intentionally excluded from the detected split plan or dist graph until real code requires/uses them.
- Do not invent generic app layers such as `services/`, `models/`, `repositories/`, `ui/`, or `commands/`; this structure classifies RisuAI host boundaries, helpers, actions, stores, and domain candidates.

## Root directory map

| Path | Guidance |
| --- | --- |
| `lua/` | Primary editable RisuLua source graph. Add or change behavior here, preserving existing `require("...")` module boundaries. |
| `legacy/` | Audit/recovery copy of the original source, usually `legacy/original.risulua`. Do not modernize or patch it unless explicitly restoring from source. |
| `docs/` | Generated plan, report, and navigation sidecars. Use them to understand why symbols moved, which modules are real, and which candidates were blocked. |
| `dist/` | Generated single-file bundle for RisuAI runtime/import. Rebuild it from `lua/` instead of editing it by hand. |
| `analysis/` / `wiki/` | Optional analyze outputs for graph/report review. Use as reference only; they should not drive source ownership over `lua/`. |
| `.risuchar` / `.risumodule` | Root marker for character-card or module targets. Use it to infer which non-Lua artifact folders are expected. |
| `assets/`, `html/`, `lorebooks/`, `regex/`, `variables/`, `toggle/`, `character/` | Non-Lua RisuAI artifact surfaces. Keep Lua changes coordinated with these only when code clearly reads or writes their variables, triggers, or content. |

## `lua/` directory map

| Path | Guidance |
| --- | --- |
| `lua/main.risulua` | Host ABI shell and composition root. Keep top-level RisuAI entry points, require bindings, bridge assignments, and preserved side effects here. |
| `lua/runtime/` | RisuAI lifecycle boundary bodies such as `start`, `input`, `output`, `button_click`, `listen_edit`, and fallback `listeners`. Keep host callback signatures stable. |
| `lua/handler_helpers/` | Helpers extracted from inside runtime handlers after capture-parameter injection. Keep them close to their owning handler and avoid broad domain refactors. |
| `lua/common/` | Pure helpers with no host writes, UI interaction, async/model/network calls, or dynamic environment dependencies. Prefer reusable low-risk utilities here. |
| `lua/host_globals/` | Public/global functions that must remain bridgeable from the RisuAI host, including duplicates and async/network actions. Preserve export names and source-order-sensitive behavior. |
| `lua/button_actions/` | Button-triggered actions from `risu-trigger` or `{{button::...}}` usage. Keep action names discoverable and verify usage with the button action index when present. |
| `lua/state/` | Extracted top-level variable tables or stores. Keep state shape stable because runtime handlers and host globals may share it. |
| `lua/prompts/` | Prompt and instruction constants such as `*_PROMPT` or `*_INSTRUCTION`. Avoid mixing executable runtime logic into this folder. |
| `lua/domain/` | Canonical semantic development surface for validated module-table domain generation. Add cohesive domain functions here, following deterministic topic paths. |
| `lua/schema/` | Coarse fallback constants target. Use only for schema-like constants created by fallback splitting, not for validated domain logic. |
| `lua/features/` | Coarse fallback bucket for uncertain domain logic or dynamic state-key code. Treat as conservative preserved logic until it can be safely classified. |
| `lua/sections/` | Section-bundle recovery fragments ordered by the split plan. These are ordered chunks, not independent require modules. |
| `lua/preload/` | `package.preload` recovery files. Preserve preload wrapper intent and do not treat them as normal domain modules unless explicitly refactored. |

## Generated docs and sidecars

| Path | Guidance |
| --- | --- |
| `docs/risulua-split-plan.json` | Machine-readable split plan and file list. Use it to distinguish planned runtime files from starter-only files. |
| `docs/risulua-split-report.md` | Human-readable split summary, generated files, recovery files, and suggested split map. Start here when orienting in an extracted workspace. |
| `docs/refactor-map.json` | Symbol-to-module dry-run map with require IDs, aliases, categories, exports, and preserved symbols. Use it before renaming or moving generated functions. |
| `docs/domain-candidates.json` | Domain candidate evidence, generated/blocked status, host effects, and grouping metadata. Use it to understand why a `lua/domain/*` path exists. |
| `docs/risulua-export-manifest.json` | Host-visible globals, duplicate groups, listener registrations, and preserved reasons. Check this before changing public/global behavior. |
| `docs/risulua-button-action-index.json` | Button action names and usage references. Check this before changing action names, signatures, or button dispatch behavior. |

## Domain grouping contract

- Domain paths must be deterministic: the same input and symbol set should produce the same `lua/domain/<topic>.risulua` or `lua/domain/<function_name>.risulua` path.
- Group by repeated strong noun tokens, normalized singular/plural phrases, limited utility families (`array`, `text`, `number`), explicitly allowed action families, or require-cycle coalescing evidence.
- Do not group functions only because they are small, adjacent, similarly shaped, or call each other; use `docs/domain-candidates.json` evidence when available.
- LLMs, embeddings, and semantic similarity are advisory only. They must not decide generated paths unless an explicit opt-in diagnostic workflow says so.

## Safe edit workflow

1. Read `docs/risulua-split-report.md` for the mode, source profile, generated file list, and packability.
2. Read the relevant sidecar (`refactor-map`, `domain-candidates`, `export-manifest`, or `button-action-index`) before moving or renaming symbols.
3. Edit the smallest relevant `lua/**/*.risulua` file and keep host APIs such as `getChatVar`, `setChatVar`, `getState`, `setState`, `reloadDisplay`, `LLM`, `request`, `json`, `Promise`, and `async` unshadowed.
4. Rebuild or validate through the project’s scaffold/extract/build command when available; never make `dist/` the source of truth.
