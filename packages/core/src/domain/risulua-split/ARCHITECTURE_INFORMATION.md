### 📂 RisuLua 모듈 아키텍처 명세서

1. `main.risulua` (메인 엔트리 포인트)

* 요약: 시스템의 초기화와 전체 흐름을 제어하는 최상위 관제 모듈
* 상세: 분산된 하위 모듈들을 하나로 병합하고, 호스트 환경(RisuAI)과의 통신 규약(ABI)을 정의하는 중추적인 역할을 수행합니다. 모든 기능이 이곳을 거쳐 파생되며, 시스템 전체를 통제하는 최종 권한을 가집니다.

2. `runtime/` (런타임 생명주기 제어)

* 요약: 시스템의 실행 주기(Lifecycle)에 맞춘 이벤트 처리 계층
* 상세: 초기화(onStart), 입력(onInput), 출력(onOutput) 등 특정 런타임 경계에서 발생하는 트리거를 감지하고, 지정된 동작이 정확한 타이밍에 실행되도록 제어하는 훅(Hook) 모듈들의 집합입니다.

3. `handler_helpers/` (이벤트 핸들러 보조)

* 요약: 런타임 이벤트 처리를 위한 내부 유틸리티 계층
* 상세: 메인 이벤트 루프의 복잡도를 낮추기 위해, 핸들러 내부에서 호출되는 종속적인 로직들을 캡슐화하여 분리해 둔 구역입니다. 런타임 모듈을 돕는 서브루틴 역할을 합니다.

4. `common/` (공통 유틸리티)

* 요약: 도메인에 종속되지 않은 순수 공용 함수 집합
* 상세: 데이터 가공, 복잡한 연산 등 시스템 전반에서 반복적으로 호출되는 독립적인 헬퍼(Helper) 로직들을 모아두어 코드의 재사용성과 효율성을 극대화합니다.

5. `host_globals/` (전역 호스트 브릿지)

* 요약: 시스템 전역에서 접근 가능한 공용 API 계층
* 상세: 내부 환경 어디서든 호출할 수 있는 글로벌 함수 및 비동기 액션을 정의합니다. 호스트 시스템의 상태에 직접적인 영향을 미칠 수 있는 강력하고 민감한 기능들을 다루는 공간입니다.

6. `button_actions/` (버튼 트리거 액션)

* 요약: 사용자 UI 상호작용에 응답하는 이벤트 모듈
* 상세: 사용자가 인터페이스 상에서 특정 버튼을 클릭했을 때 발생하는 일련의 상태 변화나 실행 액션(Action)을 개별적으로 정의하고 매핑합니다.

7. `state/` (상태 관리 스토어)

* 요약: 시스템의 휘발성 및 비휘발성 데이터를 보관하는 저장소
* 상세: 세션의 진행 상황, 전역 변수 등 런타임 동안 지속적으로 유지되고 추적되어야 하는 주요 상태값(State)들을 구조화하여 안전하게 관리합니다.

8. `prompts/` (프롬프트 및 시스템 지시어)

* 요약: AI 모델 제어를 위한 텍스트 및 상수 데이터베이스
* 상세: AI의 행동 양식이나 컨텍스트를 엄격하게 통제하는 명령어(Instruction) 집합과 프롬프트 상수들을 코드와 분리하여, 설정 변경 및 유지보수를 용이하게 합니다.

9. `domain/` (도메인 비즈니스 로직)

* 요약: 핵심 기능이 기능적/주제별로 응집된 주 개발 구역
* 상세: 카드 연산, 텍스트 파싱 등 특정 도메인(주제)에 속하는 핵심 로직들을 모듈화한 곳입니다. 기능 간의 응집도가 높아 실제 개발과 유지보수가 가장 활발하게 이루어지는 본진입니다.

10. `schema/` (정적 스키마 및 상수)

* 요약: 시스템의 기반이 되는 불변 데이터 명세서
* 상세: 런타임 중 임의로 변경되지 않아야 하는 기본 설정값, 데이터 구조(Schema), 전역 상수들을 엄격하게 정의하여 시스템의 안정성을 보장합니다.

11. `features/` (확장 피처 및 미분류 모듈)

* 요약: 특정 도메인으로 분류하기 어려운 포괄적 기능 집합
* 상세: 아직 명확한 도메인 경계가 확립되지 않았거나, 여러 환경에 걸쳐 복합적으로 동작하는 굵직한 기능(Feature)들을 임시로 수용하는 유연한 공간입니다.
